2. Introduction & Overview

System Purpose

The Bus Fleet and Ticketing Management System is a comprehensive platform designed to centralize fleet tracking, streamline ticket management, and monitor daily revenue. It provides an authoritative control center for administrators to oversee operations, ensure efficient dispatching, and maintain financial integrity.

Target Audience

This manual is specifically tailored for:

  • System Administrators: Responsible for configuring system-wide settings, managing user accounts, and overseeing technical operations.
  • Dispatchers: Focused on day-to-day fleet operations, monitoring active trips, and tracking driver remittances.

System Requirements

  • A modern web browser (Google Chrome, Mozilla Firefox, Microsoft Edge, or Safari).
  • An active, stable internet connection to ensure real-time dashboard updates and live GPS tracking functionalities.

3. Getting Started

Access & Authentication

To access the administrative features, authorized personnel must authenticate through the secure portal.

  1. Accessing the Portal: Open your web browser and navigate to the admin portal via Admin_index.php.
  2. Logging In: Enter your authorized administrator credentials (Username and Password) into the provided fields and click the Login button.
  3. Logging Out: To securely end your session and prevent unauthorized access, locate your profile icon in the upper right corner of the dashboard and select Logout. Always log out when stepping away from your workstation.

4. Interface Guide & Navigation

Dashboard Overview

Upon successful login, you are directed to dashboard.php. This is the central hub of the system, displaying critical operational metrics such as the number of active buses, on-duty drivers, real-time ticket sales, and total revenue for the day.

[Insert Screenshot: Dashboard Overview]

Navigation Menu

The primary navigation menu is located on the left-hand sidebar. It provides quick access to the following modules:

  • Buses: Access buses.php to view the entire fleet. Use add_bus.php to register new vehicles and edit_bus.php to update existing vehicle details.
  • Drivers: Navigate to drivers.php to oversee driver profiles or use add_driver.php to register new drivers.
  • Passengers: Access passengers.php to manage passenger accounts and review ticketing histories.
  • Trips: Go to trips.php to monitor scheduled and active routes. View associated passenger tickets via get_trip_tickets.php.
  • Remittance: Access remittance.php to track financial deposits and verify expected shift earnings from drivers.
  • Reports: Generate and view system analytics via reports.php.
  • Security: Navigate to security.php to manage system settings, permissions, and security logs.

Icons & Symbols Legend

  • Active (Green Toggle / Icon): Indicates an operational bus, an active user account, or a trip currently in progress.
  • Inactive (Gray/Red Toggle): Indicates an out-of-service bus or a suspended account. These statuses can be changed using api_toggle_status.php.
  • Force End Warning (Red Triangle): Represents the action tied to api_force_end_trip.php. This icon indicates a trip that has been manually aborted due to an emergency or system error.

5. Core Operating Instructions (The Workflows)

Managing the Fleet: Adding a New Bus and Assigning a Handler

  1. Click on Buses from the navigation menu to open buses.php.
  2. Click the Add New Bus button to navigate to add_bus.php.
  3. Input the required vehicle data, including Plate Number, Capacity, and Model. Click Save to register the vehicle in the system.
  4. Return to the fleet list in buses.php and locate the newly added bus. Click Assign Handler.
  5. You will be directed to assign_bus_handler.php. Select an available driver from the dropdown menu and click Confirm Assignment.

Monitoring Operations: Viewing Live Locations and Managing Trips

  1. To view live fleet locations, navigate to the Map/Tracking widget on the Dashboard. This feature pulls real-time coordinate data via get_fleet_locations.php.
  2. To monitor specific routes, click Trips (trips.php) from the navigation menu.
  3. Locate an active trip and click View Tickets to see the passenger manifest, driven by get_trip_tickets.php.
  4. Using the Force End Trip Function: In the event of a bus breakdown or emergency, locate the active trip on the Trips page and click Force End Trip. This action executes api_force_end_trip.php and immediately concludes the trip to prevent further bookings. Confirm the warning prompt to finalize. Note: Use this function strictly as a last resort.

Financial Management: Configuring Fares and Viewing Remittances

  1. Configuring Fare Settings: Click Financials, then Fare Settings to open fare_settings.php. Adjust the base fare and per-kilometer rates as necessary, then click Update Fares to apply the new logic system-wide.
  2. Reviewing Remittances: Click Remittance (remittance.php) in the navigation menu. Select a driver or date to review their completed shifts, expected ticket revenue, and cash turned over to the office.

Reporting: Generating, Printing, and Exporting Data

  1. Navigate to Reports (reports.php) via the left-hand menu.
  2. Select your desired report type (e.g., Revenue, Passenger Volume) and define the date range.
  3. To print the document for physical filing, click Print Report, which invokes print_report.php in a printer-friendly layout.
  4. To export the data for spreadsheet software (like Microsoft Excel), click Export to CSV. The system will download the file via export_csv.php.

6. Troubleshooting & FAQs

Common Errors & Resolutions

  1. Error: Failed CSV Export
    • Symptom: Clicking Export to CSV does not download a file.
    • Resolution: Check if your browser is blocking pop-ups or automatic downloads. Ensure you have selected a valid date range. If the dataset is too massive, try generating the report in smaller date increments.
  2. Error: Inactive Driver Status
    • Symptom: You cannot assign a specific driver to a bus.
    • Resolution: The driver’s account may be suspended. Navigate to Drivers (drivers.php), locate the driver, and check their status toggle. Click the toggle to invoke api_toggle_status.php and switch them back to Active.
  3. Error: GPS Location Not Updating
    • Symptom: A bus location appears frozen on the map (get_fleet_locations.php).
    • Resolution: Contact the driver to ensure their mobile device has location services enabled and is connected to the internet.

Frequently Asked Questions

  • Q: When do adjustments made in Fare Settings take effect?
    A: Any changes made in fare_settings.php apply immediately to all new tickets booked after the update. Active trips and already-purchased tickets retain the old rate.
  • Q: Can a deleted passenger account be recovered?
    A: No. When an administrator deletes an account using api_delete_account.php, the action is irreversible to comply with data privacy standards. The user must register a new account.
  • Q: What happens to ticket records when I use "Force End Trip"?
    A: When api_force_end_trip.php is executed, all previously purchased tickets remain valid in the system history for auditing purposes. However, the trip is abruptly marked as completed, and no further transactions can occur for that specific schedule.

7. Appendices & Support

Glossary

  • Force-End: An emergency administrative override that immediately terminates an active trip.
  • Kiosk Integration: The frontend scripting (kiosk_logic.js) that synchronizes the backend database with physical self-service ticketing machines at terminals.
  • Ph-Address-Selector: A localized utility script (ph-address-selector.js) ensuring standardized Philippine address formatting during user registration and management.
  • Remittance: The expected cash value of all physical tickets sold by a driver or conductor during their assigned shift, which must be surrendered to the administration.
  • Trip Ticket: The digital or physical receipt proving a passenger's payment and seat reservation for a specific trip schedule.
